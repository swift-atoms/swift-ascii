# swift-ascii

Use this package when you read or write bytes as ASCII text: naming characters by their ASCII names, classifying and case-converting bytes, normalising line endings, and converting integers and decimal floating-point numbers to and from ASCII digits. Start from `ASCII.Code`, one ASCII character held as a byte, and `ASCII.Classification`. To read numbers, use `ASCII.Decimal.Parser`, `ASCII.Hexadecimal.Parser`, `ASCII.Octal.Parser`, `ASCII.Binary.Parser` or `ASCII.Decimal.Float.Parser`. To write them, use `ASCII.Decimal.Serializer`, `ASCII.Hexadecimal.Serializer`, `ASCII.Octal.Serializer` or `ASCII.Binary.Serializer`. `ASCII.Decimal.Coder` does both from one configuration. To give your own byte carrier ASCII constants, use `ASCII.Namespace` through the `ascii` member on `Carrier.Protocol`. For Unicode text, use `Swift.String`. To turn byte offsets in source text into line:column locations, use the sibling swift-text.

## Laws

- Classification works on byte values, not Unicode properties. Whitespace is exactly HT, LF, CR and SP: VT and FF do not count. Control is 0x00 to 0x1F plus DEL. Printable is 0x20 to 0x7E, and visible is the same range without SP. A byte at or above 0x80 satisfies no classification predicate. `ASCII.Classification.isAllLowercase` and `ASCII.Classification.isAllUppercase` hold when no letter of the other case occurs, so input that is empty or holds only digits satisfies both.
- Case conversion changes only A to Z and a to z. Every other byte, and every non-ASCII `Swift.Character`, comes back unchanged.
- `ASCII.normalized(_:to:)` treats a CRLF pair, a lone CR and a lone LF each as one line ending and replaces each with the target ending. Input that contains neither CR nor LF comes back byte for byte.
- The integer parsers read an optional sign, then digits of their radix, and stop before the first byte that is not such a digit. That byte stays in the input. Hexadecimal letters are accepted in either case. On any failure, the input is restored to where the parse began. A negative count is rejected before any byte is read.
- With `ASCII.Digits.Sign.none`, a leading plus or minus sign is not consumed, so the parse fails for lack of digits. With `ASCII.Digits.Sign.optional`, a minus sign is accepted only when the output type is signed. Negative numbers accumulate towards the type's minimum, so that minimum parses without overflow. Overflow is checked after every digit, and it fails the whole number.
- `ASCII.Digits.Count.exactly` fails unless exactly that many digits are present, and it never reads a further digit. A count of exactly zero always fails. `ASCII.Digits.Count.atMost` stops after that many digits and needs at least one.
- `ASCII.Decimal.Float.Parser` reads an optional sign, digits, an optional point followed by digits, and an optional exponent: e or E, an optional sign, then digits. It needs at least one digit before or after the point. An exponent marker that has no digits after it is left in the input. The result is the correctly rounded `Double`, bit-identical to what `Swift.Double` produces from the same text, including negative zero and subnormal values. An exponent beyond the representable range gives zero or infinity with the parsed sign rather than a failure. There is no syntax for infinity, NaN or hexadecimal floating-point numbers.
- The serializers write the canonical spelling: no plus sign, no leading zeros, a single 0 for zero, and a leading minus sign for negative values. `ASCII.Hexadecimal.Serializer` writes lowercase letters, but `ASCII.Hexadecimal.code(_:case:)` defaults to uppercase. Every serializer appends to the buffer and leaves its existing contents intact. `ASCII.Decimal.serialize(_:into:)` handles integers up to 128 bits wide, including each type's minimum.
- `ASCII.Decimal.Coder` counts the digits of the magnitude and leaves out the sign. `ASCII.Digits.Count.exactly` pads with zeros between the sign and the digits, and `ASCII.Digits.Count.atMost` never pads. A value with more digits than the count fails. Every configuration failure is thrown before any byte is appended. With `ASCII.Digits.Count.greedy`, parsing and then serializing gives the canonical spelling rather than the original text: an explicit plus sign and leading zeros are dropped.
